# Intel N100/N150 mini PC setup (Beelink and friends)

The Pi 5 has no video encoder, so its YouTube push is a stream copy:
whatever bitrate the camera sends is the bitrate the field uplink must
carry. An Intel N100/N150 has QuickSync — so the box can **record the
camera at full quality locally** (crisp clips) while **pushing YouTube a
smaller stream** the uplink can actually manage. That split is the whole
reason to run the encoder on x86.

Everything below was written on a Beelink Mini S13 (N150, 12 GB RAM,
512 GB SSD) but applies to any N100/N150-class mini PC.

**AMD boxes** (Ryzen mini PCs — Vega/VCN graphics) work too: the
installer sets up Mesa's VA-API driver and the same real-test-encode
probe decides what the box can do. Expect somewhat softer 1080p at the
same bitrate than QuickSync, and prefer H.264 push mode on older AMD
chips. For a uniform fleet, the N100/N150 remains the recommended SKU.

## 1. Put Debian on it

The box ships with Windows. The encoder wants Debian 13 (Trixie),
64-bit, no desktop — 13 specifically: its kernel knows the N150's
Twin Lake iGPU, which is where QuickSync lives. (Debian 12's older
kernel may not expose the video encoder on this chip at all.)

1. On another computer, download the **Debian 13 amd64 netinst ISO**
   (debian.org → Download — the current stable IS 13) and write it to
   a USB stick with balenaEtcher or Rufus.
2. Plug the stick, a keyboard, and a monitor into the mini PC. Power on
   and tap **F7** (Beelink; sometimes DEL) for the boot menu; pick the
   USB stick.
3. Run the normal (non-graphical is fine) install. The only choices that
   matter:
   - Erase the whole disk (Windows goes away — that's fine, this box is
     an appliance now).
   - Hostname: whatever you like (`playcall-n150` reads well).
   - Create a user for yourself (you'll `sudo` from it).
   - At **Software selection**: tick **SSH server** and **standard
     system utilities**, untick every desktop.
4. Reboot into Debian, log in, and get root once for the installer:
   `su -` (or log in as your user and use `sudo` after
   `apt install sudo && usermod -aG sudo YOURUSER`).

Plug it into **Ethernet** if you possibly can. The Beelink's 2.5 G LAN
port is the most reliable path for a 10 Mbps camera feed plus the
YouTube push; Wi-Fi 6 works but is the first thing to wobble at a park.

> **Installed over Wi-Fi and Ethernet seems dead?** Debian only
> configures the interface used during the install, so a cable plugged
> in later does nothing (`ip a` shows the port `DOWN`, no address). The
> encoder installer fixes this itself — it adds a plug-and-play DHCP
> config for every unconfigured wired port. On a box installed before
> that shipped, re-run the install one-liner (idempotent), or by hand:
>
> ```
> sudo tee /etc/network/interfaces.d/enp1s0 <<'EOF'
> allow-hotplug enp1s0
> iface enp1s0 inet dhcp
> EOF
> sudo ifup enp1s0
> ```
>
> (Swap `enp1s0` for the port name `ip a` shows.) Once Ethernet has an
> address, retire Wi-Fi: `sudo ifdown wlo1` and delete its lines from
> `/etc/network/interfaces`.

## 2. Install the encoder

On the website: **Score Bug Studio → Encoders → ➕ Add an encoder**. It
gives you a one-line command with your activation code baked in — paste
it into the box's terminal:

```
curl -fsSL https://basebook.org/i | sudo bash -s -- YOUR-CODE
```

Fresh Debian doesn't ship curl (the Pi images do). Either install it
first — `sudo apt update && sudo apt install -y curl` — or use wget,
which IS there:

```
wget -qO- https://basebook.org/i | sudo bash -s -- YOUR-CODE
```

(And if `sudo` itself is missing or refuses you, a root password was
set during install: `su -`, then `apt install -y sudo curl &&
usermod -aG sudo YOURUSER`, log out and back in.)

The installer detects x86 and additionally sets up hardware encoding:
the **non-free** Intel VA-API driver (the free one decodes but cannot
encode on this silicon — the installer enables Debian's non-free
component itself if it has to) and render-node permissions for the
service user. It ends with a **QuickSync verdict** line — a real test
encode, not a guess:

```
QuickSync: H.264 hardware encode WORKS — pick the YouTube quality
on the game page's encoder card (📺) once the box shows online.
```

If it prints the ⚠ warning instead, run the suggested `apt install`,
reboot, and re-run the installer (it's idempotent — re-running is
always safe and never touches your pairing).

Because the box is already online over Ethernet, the installer ADOPTS
the network as-is: no hotspot, no Wi-Fi management. It prints the
camera RTMP URL(s) and the settings-page address when it finishes.

🎧 **Coach comms installs along with it** on a paired box — the spoken
pitch calls and the coach's live voice into Bluetooth buds. Its
manager lives on `http://<box>:8790` (pair buds, label 🧢 catcher /
⚾ pitcher, lock Bluetooth); the encoder settings page's comms card
shows its status and links there.

## 3. Send it high-quality video

Point your camera app (Mevo, Larix, the phone camera page's "Field Pi"
mode, OBS…) at the box's ingest URL from the install banner /
Score Bug Studio:

```
rtmp://<box-address>:1935/live/<ingest-key>
```

Set the CAMERA to the good stuff — **1080p, 8–10 Mbps, H.264**. That
full-quality stream is what gets recorded locally and cut into clips.
(HEVC in from the camera also records and clips fine; see the note at
the bottom before choosing it.)

## 4. Pick the YouTube quality — from the website

On the game page's encoder card you'll see **📺 YouTube quality** once
the box heartbeats (the selector only appears for boxes that proved
they can encode):

- **Match camera (copy)** — push exactly what the camera sends
  (Pi behavior).
- **2.5 / 3 / 4 / 6 Mbps** — QuickSync re-encodes the push down to that
  bitrate. The local recording and every clip keep the camera's full
  quality; only the YouTube leg shrinks.

Changing it mid-stream restarts the push leg within a few seconds. For
a typical field hotspot, **3 Mbps** is the sweet spot: stable 1080p on
YouTube from a 10 Mbps camera feed.

## 5. Radar

Same as the Pi — see **[RADAR.md](RADAR.md)** for the gun settings
(19200 8N1, continuous mode) and the Bluetooth adapter (BT578) setup.
The short version:

- Plug the gun's USB-serial cable (and the LED board's, if you use it)
  into any USB ports — the box **listens for real velocities** to work
  out which cable is which, and once proven it writes the roles to
  config so reboots and port swaps don't matter.
- Test from the website: game page → **🔫 Radar test** shows live
  readings, per-port verdicts, and the radar log tail.
- Bluetooth gun: set `radar.bluetooth_mac` in the box settings, pair
  once, reboot — `/dev/rfcomm0` then behaves like a cable.

## 6. Storage

Recordings land on the internal SSD (`/var/lib/playcall-encoder`) — on
a 512 GB box that's days of rolling recording with nothing to
configure, and the storage watchdog reports free space and write
health to the website like always.

Moving an existing NVMe recordings drive in (label `playcall-video`)
also works: add it to `/etc/fstab` mounted at the data path, and the
watchdog will insist on it from then on.

## HEVC to YouTube

QuickSync on the N150 encodes HEVC, YouTube accepts it over enhanced
RTMP, and Debian 13's ffmpeg speaks it — so the encoder now offers it.
On a box that PROVES both halves (a real test encode AND a test mux
into flv), the 📺 quality selector grows **HEVC options** (2/2.5/3/4
Mbps): ~35% more quality per bit on the same field uplink, and viewers
notice nothing — YouTube transcodes for playback either way. H.264
stays the default and the automatic fallback: a Pi, an old ffmpeg, or
an unproven driver quietly pushes H.264 (or copy) with a log line,
never an error loop. The same choice lives on the box's own settings
page.
